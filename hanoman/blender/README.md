# Hanoman Duta — Blender asset scripts

Every 3D asset of the demo is generated by Python (`bpy` 4.5 as a pip module, no manual Blender work).

```
python3 hanoman/blender/characters.py [ids] [--no-preview] [--no-export]   # hanoman rama jembawan sugriwa
python3 hanoman/blender/enemies.py    [ids] ...                            # wil cakil buto_ijo banaspati yuyu kijang kijang_raksasa
python3 hanoman/blender/bosses.py     [ids] ...                            # sura baya
python3 hanoman/blender/props.py      [ids] ...                            # environment + pickups
python3 hanoman/blender/portraits.py  [ids]      # 768x1024 transparent placeholder portraits
python3 hanoman/blender/title.py      [--fast]   # 1920x1080 title key art -> portraits/title.png
python3 hanoman/blender/verify_glb.py [ids]      # re-import GLBs, print hierarchy / pivots / tris / winding
```

Outputs: `game/assets/models/<id>.glb`, previews (game camera 55° + front + side inset) in
`blender/previews/<id>.png`, portraits in `game/assets/portraits/<id>.png`.
A full rebuild with previews takes ~10 min on 4 CPU cores (`--no-preview` is fast).

## Contract

* 1 unit = 1 m, Blender Z up, **front = -Y**, feet/base on z = 0. glTF export (+Y up) turns this into
  Godot **+Y up, front = +Z** (Blender -Y → Godot +Z, Blender +X → Godot +X, Blender Z → Godot Y).
* One root node `<id>`. No armatures, animations, cameras or lights; modifiers applied.
* Characters/enemies/bosses: pivot Empties at the joints (all with identity rotation, so local axes =
  root axes). Each pivot has at most one mesh child named `<pivot>_mesh` (all parts of that pivot joined).
  Rotate the pivots from code. Axis signs are the same in Blender and Godot (X maps to X):
  a **negative rotation about X swings a hanging arm/leg forward**; a positive X rotation opens a jaw
  (jaws point forward); `claw_*` and the `peti` lid open with a negative X rotation.
* "left/right" = the character's own side: `_l` is at **+X** (Blender and Godot), `_r` at -X.
* Materials: flat Principled base colour, roughness 0.8, no textures, 2–5 per asset, names `M_<Surface>`.
  Emissive: `M_Glow*` (emission colour = base colour, strength 2). Pickup `orb_dewa` core `M_GlowOrb` is
  white so the game can tint it per god.
* Budgets: characters ≤ 6000 tris, props ≤ 1500 (arca 1652), bosses ≤ 12000.

## Portraits (`game/assets/portraits/`)

`hanoman rama jembawan sugriwa sura baya kijang dewa_bayu dewa_surya dewa_baruna dewa_indra` —
768×1024 RGBA, toon + Freestyle ink + coloured rim, paper grain. The god figures exist only in
`portraits.py` (no GLB). `title.png` — 1920×1080 opaque key art (upper ~25 % kept dark for the logo).
All are placeholders for painted Higgsfield art.

## Gotchas

* Blender -Y front → Godot +Z front: a character looks down Godot +Z, so `look_at()` (which aims -Z)
  needs a 180° flip or use `basis = Basis.looking_at(-dir)`.
* Object names are exact node names; mesh nodes are `<pivot>_mesh`. Godot may add `.glb.import` files
  next to the models — they are not produced here.
* Scripts rebuild the scene from factory settings per model, so names never get `.001` suffixes.
* Previews/portraits use Cycles (CPU) with a Toon BSDF material swap and Freestyle; Eevee is not used
  (it needs a GPU context headless). Workbench also works headless if a quick look is enough.
